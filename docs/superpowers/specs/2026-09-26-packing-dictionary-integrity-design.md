# 行囊字典完整性设计

## 目标

让行囊物品的类别、标签和收纳位置在页面更新、刷新及跨设备使用时保持稳定，并避免误删仍有物品的类别。

## 共享字典

- 使用共享存储中的单一行囊字典记录，保存自定义类别、类别名称、删除标记、类别排序、标签关联、行囊名称、行囊父级、图标及自定义行囊。
- 页面加载时优先恢复该记录；本地存储保留为离线副本和旧版本迁移来源。
- 载入后会从所有行囊物品反向补齐缺失的类别和标签关联，不改写物品的 `subcategory` 或 `property`。
- 类别和标签的展示与表单选项只使用恢复后的字典。未知历史类别会被恢复为可见类别，而不是被显示层静默改为“其他”。
- 行囊父级解析使用当前行囊树，适用于系统行囊和自定义行囊。

## 删除类别

- 空类别可直接删除。
- 含物品的类别点击删除后显示迁移对话框，列出物品数量与目标类别选择器；当前类别不可作为目标。
- 对话框生成四位互不重复数字。用户必须原样输入该数字，且选定目标类别，确认按钮才可用。
- 确认时所有受影响物品迁移到目标类别，`property` 设为空字符串（无标签）；名称、数量、人物归属、使用次数、完成状态、行囊和内置收纳包位置保持不变。
- 物品批量保存成功后才移除类别、该类别的标签关联和类别显示配置。

## 行囊分配

- 行囊用途树的每个行囊提供“按类别放入”操作。用户选择一个类别后，该类别全部物品转移到所选行囊；批量操作仅更新 `luggage` 与 `container`。
- 行囊明细中的单个物品提供“转移行囊”操作，可选任意当前有效的主行囊或内置收纳包。
- 选择内置收纳包时，物品的 `container` 设为内置收纳包，`luggage` 设为其主行囊；选择主行囊时，两者均设为该主行囊。

## 验证

- 自动测试覆盖：共享字典记录、历史类别/标签恢复、受保护删除的目标与随机码要求、迁移后无标签、批量按类别入包及单件转移自定义行囊。
- 浏览器测试覆盖类别删除弹窗与两种行囊转移后的即时渲染。
