# 行囊物品属性设计

## 目标

把行囊新增流程中的类别、归属和物品属性明确化，减少长标签，同时让消耗品的可用次数只在需要时出现。

## 数据

- 行囊类别展示为：证件、衣物、洗护、药品、电子、户外；现有类别键和已存数据不变。
- 行囊物品新增 `property`：`common`（常用）、`appliance`（电器）、`consumable`（消耗品）。旧数据缺失时按 `common` 展示。
- 只有 `consumable` 使用 `usesTotal` 与 `usesRemaining`；其余属性不写入次数。
- 采购项保存同一 `property` 与（仅消耗品的）`usesTotal`，提交到行囊后保留它们；归属仍初始为待分配。

## 交互

- 行囊明细新增表单依次提供类别、归属、物品属性；属性为消耗品时才显示标记为“可用次数”的数字输入。
- 采购清单提供物品属性和同样的条件数字输入。
- 行囊用途、人物归属和物品类别筛选区均有小标题和一句说明。归属保持单选。
- 物品卡显示属性标签；消耗品继续显示“使用一次”和余量。

## 验证

- 静态测试验证短类别、表单字段、条件次数控件与属性保留逻辑。
- 浏览器测试验证选择消耗品时显示次数，切回其他属性时隐藏；新增物品保存归属及属性。
